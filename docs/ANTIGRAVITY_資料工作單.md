## T2　放錯欄位的條件

比對時，放錯欄位的內容會變成只有一份標準有的「獨有」列，與其他標準對不起來。已知案例：

- `GB31241-6.1`（高溫外部短路）：`apparatus`（治具與設備）的值是「表面達溫後保溫 30 分鐘」，這是前置處理／溫度穩定程序，不是治具。應移到對應的程序或溫度欄位，治具欄改填原文的短路治具（若原文未規定則刪除）。

請以 `scripts/review/field_inventory.mjs` 掃全庫，找出「值的內容與欄位標籤不符」的情形（例如治具欄寫時間、溫度欄寫判定），列表後由主代理逐筆確認再改。

## T3　測試代號唯一化

`UL1642` 與 `UL1642-2022` 共用 11 個測試代號（`UL1642-T10`～`UL1642-T20`）。網址 `?test=UL1642-T15` 無法分辨版本（前端目前取較新版本），驗收腳本也會判為「代號不唯一」。

建議：`UL1642-2022.json` 的測試代號改為 `UL1642-2022-T10` 等，同步 `test_sequence` 與任何引用；改完跑 `npm run validate`。前端不需修改。

## T4　寫法統一（降低「寫法不同」列）

v2 比對頁會把「數值相同、只是寫法不同」的列標為「寫法不同」，不計入差異，但仍會出現在畫面上。`npm run check:wording`（`near_same.mjs`）目前 429 列。照 2026-11-05 的做法分批統一寫法，並調降 `scripts/review/near_same_baseline.json`。
